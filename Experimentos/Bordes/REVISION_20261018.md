# Revisión de `gondola_bordes.py`

Fecha: 18 de octubre de 2026.

Actualización del 20 de octubre: se implementó una capa de integración y se
ejecutó una primera comparación sobre validación de desarrollo. El original de
Paulo sigue conservado. Ver el [experimento combinado V2](../../Documentacion/Experimento_YOLO_Paulo_v2.md)
para el estado actual; el resto de este documento describe la revisión inicial.

El script tiene una base útil para experimentar con análisis local dentro de los
niveles detectados por YOLO. Su porcentaje actual representa celdas que cumplen
heurísticas de bordes/color; aún no demuestra ocupación real por productos.
No se modificó el script ni se integró al panel durante esta revisión.

El criterio vigente del lote Líder Express es `disponibilidad_visual_nivel_v2_reponer`
(guía del 17 de octubre): `reponer` agrupa vacío y menos del 30 % del ancho con
producto; `suficiente` corresponde al 30 % o más; `no_evaluable` se usa cuando no
se puede decidir. La propuesta debe evaluarse con estos tres estados. El código
actual de `Herramientas/Modelos/niveles_modelos.py` y los modelos anteriores aún
usan cuatro estados; adaptar exportación, entrenamiento e interpretación de
resultados antes de entrenar con el lote nuevo.

## Qué hace y qué se puede reutilizar

- El usuario dibuja rectángulos por nivel y el programa los conserva en JSON.
- `mapa_bordes` combina filtros, Canny y cierre morfológico.
- `quitar_lineas_largas` intenta eliminar estructura del estante con Hough.
- `analizar` divide cada recorte en una grilla y marca celdas por densidad de
  bordes o proporción de píxeles saturados/oscuros; luego limpia la grilla.
- `dibujar` permite inspeccionar visualmente la hipótesis de ocupación.
- `prueba_estres` mide variación ante perturbaciones, aunque no exactitud.

La separación entre editor, análisis y dibujo permite reutilizar `analizar`
sin abrir ventanas: los rectángulos podrían venir de nuestras detecciones.

## Hallazgos principales

1. **La magnitud no coincide con nuestro criterio.** En la línea 167 se divide
   el número de celdas positivas por todas las celdas del recorte: es una fracción
   de área de grilla. Nuestro criterio compara ancho con producto y ancho del
   nivel. Productos bajos a lo largo de todo el nivel podrían recibir un
   porcentaje pequeño. No aplicar directamente nuestro umbral de 30 % a `pct`.
2. **Color y oscuridad pueden dominar el resultado.** Las líneas 156–160 marcan
   como ocupadas zonas saturadas u oscuras aunque no tengan bordes. Un fondo
   oscuro o de color puede aparentar ocupación completa. Esto requiere distinguir
   producto de fondo, no solamente cambiar el nombre del porcentaje.
3. **Falta representar imposibilidad de medir.** En las líneas 142–144, un recorte
   demasiado pequeño devuelve 0 %, pese a que no se analizó. Tampoco se detectan
   personas u otras oclusiones. En una integración, esos casos requieren un valor
   ausente y una razón; no deben disparar una alerta de vacío. Conservar el estado
   no evaluable y evitar que esta heurística lo convierta automáticamente en vacío.
4. **Parámetros dependientes de escala y contexto.** Las celdas, filtros y grosor
   de borrado usan píxeles fijos. El mínimo de longitud de líneas usa el ancho de
   toda la fotografía, no el del nivel. Conviene normalizar la escala de trabajo
   y comprobar estabilidad con distintas resoluciones. Hough elimina líneas en
   cualquier ángulo: también puede borrar bordes rectos de productos.
5. **Rectángulos frente a nuestras máscaras.** Un rectángulo alrededor de un nivel
   inclinado puede incorporar otros niveles y estructura. Para la integración se
   necesita limitar el cálculo a la máscara válida y, si corresponde, rectificar
   la perspectiva. No sustituir los píxeles exteriores por negro: activarían la
   regla de oscuridad. Excluirlos tanto de las señales como del denominador.
6. **Preparación para uso compartido.** La salida predeterminada apunta a
   `E:\openCV\fotos`; usar una ruta del experimento. Validar cajas y parámetros
   antes de analizar: una caja fuera de la imagen produjo un error de OpenCV.
   Para comparar ejecuciones, guardar resultados numéricos, parámetros y geometría,
   además de las imágenes. La prueba de estrés no sustituye referencias humanas;
   un resultado estable también puede estar equivocado.

## Comprobación ejecutada

Se importó el módulo sin abrir el editor y se llamó a `analizar` con imágenes
artificiales en memoria, usando los parámetros predeterminados. Entorno local:
Python 3.12.14, OpenCV 4.11.0 y NumPy 1.26.4. Para las filas siguientes se usó
una imagen de 720 × 240 y una caja que cubría toda la imagen, salvo donde se indica.

| Entrada controlada | Resultado `pct` |
|---|---:|
| Fondo uniforme blanco, BGR (255, 255, 255) | 0 % |
| Fondo uniforme gris, BGR (180, 180, 180) | 0 % |
| Fondo uniforme oscuro, BGR (40, 40, 40) | 100 % |
| Fondo uniforme rojo, BGR (20, 20, 220) | 100 % |
| Franja roja en todo el ancho y 20 % inferior de altura, sobre blanco | 22,2 % |
| Franja roja en todo el ancho y 50 % inferior de altura, sobre blanco | 55,6 % |
| Franja roja en todo el ancho y 80 % inferior de altura, sobre blanco | 100 % |
| Caja de 20 × 20 sobre fondo oscuro | 0 %, sin grilla |
| Caja (800, 0, 120, 120), fuera de la imagen | Error al redimensionar recorte vacío |

Las franjas se dibujaron con `cv2.rectangle` desde y = round(240 × (1 − altura))
hasta y = 239 y desde x = 0 hasta x = 719. Estos casos verifican comportamiento
del algoritmo; no son fotografías de góndolas ni una medición de precisión.
No se utilizaron imágenes de la reserva final ni se entrenaron modelos.

## Integración propuesta

Primero, mantener YOLO como localizador y clasificador y añadir esta señal como
resultado experimental paralelo. El punto de conexión está en
`Herramientas/Modelos/panel_worker.py`, donde ya tenemos máscara, clase y confianza
por detección (líneas 88–96). No requiere reentrenar YOLO para ese primer ensayo.

Antes de derivar estados desde la grilla, definir cómo identificar presencia de
producto a lo largo del ancho del nivel. Una proyección por columnas es una opción
a evaluar, con tolerancias para ruido y oclusión; no basta con contar cualquier
celda positiva de una columna. Validar esta definición con referencias humanas.

Comparar sobre las mismas fotos de desarrollo los estados de YOLO, las señales de
bordes/color y la combinación. Incluir vacíos, niveles bajos, envases lisos y bajos,
fondos oscuros, perspectiva, productos al fondo y oclusiones. Medir error del ancho
ocupado contra referencias y falsas alertas/omisiones por estado. Ajustar en
desarrollo y conservar escenas independientes para evaluación final.
